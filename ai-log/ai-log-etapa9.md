# Jurnal utilizare AI - Etapa 9

**Sarcina:** Înlocuirea serverului mock `json-server` cu un backend propriu în Node.js + Express 5 (`backend/`), cu rute REST complete pe `/telefoane`, validare strictă pe server cu listă albă de câmpuri, configurare CORS restrictivă, tratare centralizată a erorilor, actualizarea `frontend/src/api.js` și eliminarea completă a `json-server` și `frontend/db.json`.

**Descrierea interacțiunii:**
1. **Configurare proiect backend:** Am actualizat `backend/package.json` pentru module ES (`"type": "module"`, `"main": "src/server.js"`, scripturile `"start"` și `"dev"` cu `node --watch`), am creat `backend/.gitignore` (`node_modules`, `.env`) și `backend/.env.example` (`PORT=3001`, `CORS_ORIGIN=http://localhost:5173`) și am sincronizat `backend/package-lock.json`.
2. **Validare pe server (`backend/src/validation.js`):** Am implementat constanta `STARI = ["nou", "resigilat", "second-hand"]` (sincronizată cu `frontend/src/constants.js`), funcția `valideazaTelefon(body, { partial })` cu listă albă pentru câmpurile permise (`titlu`, `stare`, `pret`, `inStoc`) pentru a preveni mass-assignment și funcția `parseId()` pentru validarea strictă a ID-urilor întregi pozitive.
3. **Rute REST și aplicația Express (`backend/src/routes/telefoane.js`, `app.js`, `server.js`):** Am implementat cele cinci rute REST (`GET /telefoane`, `GET /telefoane/:id`, `POST /telefoane`, `PATCH /telefoane/:id`, `DELETE /telefoane/:id`) pe date în memorie, cu codurile HTTP corecte (`200`, `201`, `204`, `400`, `404`), plus separarea `app.js` (CORS pentru `http://localhost:5173`, `express.json()`, `GET /health`, handler `404` și middleware centralizat de erori cu 4 parametri care nu expune detalii interne la `500`) de `server.js`.
4. **Conectare frontend și eliminare `json-server`:** Am actualizat `request()` în `frontend/src/api.js` pentru a extrage `body.error` din răspunsurile non-2xx ale serverului propriu, am șters `frontend/db.json`, am eliminat `json-server` și scriptul `"api"` din `frontend/package.json` și am rulat `npm install` în `frontend/` pentru actualizarea `frontend/package-lock.json`.
5. **Verificare:** Am testat cu `curl` toate rutele (`GET`, `POST`, `PATCH`, `DELETE`, `/health`, ID invalid `400`, element inexistent `404`, date invalide `400`, protecție mass-assignment, antet CORS) și am verificat `npm run lint` și `npm run build` în `frontend/` fără erori.
